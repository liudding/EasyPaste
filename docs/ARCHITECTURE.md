# EasyPaste 系统架构与设计文档

> 范围：当前仓库（SwiftPM 可执行 target，`swift-tools-version: 6.2`，macOS 15+，AppKit + SwiftUI 混合）。
> 目的：说明核心模块划分、职责边界与端到端数据流。配套图见 [`architecture_diagram.svg`](./architecture_diagram.svg)。

---

## 1. 总体架构

EasyPaste 是一个 **菜单栏常驻的剪贴板管理器**。它持续监听系统 `NSPasteboard`，把每次拷贝的**多格式原始数据**保真抓取、归类、存储，并通过快捷键唤出的**屏幕边缘面板**实现快速检索与跨应用粘贴。

整体采用 **内存单一事实源 + 写穿持久化（write-through）** 的架构：

- **内存为真相**：`ClipboardStore` 在内存持有 `items / boards / rules`，UI 直接读内存，零延迟。
- **SQLite 为耐久性**：每次变更在同一事务内写穿到 GRDB（`clips` + `clip_blobs`），启动/被杀后从库重建内存。
- **无外键设计**：所有关联（看板、规则目标）以普通 `UUID TEXT` 存储，应用层解析，为阶段二 Harmony / CloudKit 同步预留空间。

### 分层（自外向内）

| 层 | 职责 | 主要类型 |
|----|------|----------|
| **外部系统** | 系统粘贴板、前台 App、辅助功能、iCloud | `NSPasteboard` / `NSWorkspace` / AX / ubiquity |
| **输入/捕获** | 轮询粘贴板、全局热键 | `ClipboardService` · `GlobalShortcutService` |
| **应用核心** | 状态管理、持久化、组合根、备份、缓存 | `AppServices` · `ClipboardStore` · `DatabaseManager` · `BackupService` · `AppIconCache` · `ImageSizeCache` |
| **展示/交互** | 屏幕边缘面板、菜单栏、设置、引导 | `PanelController` · `PanelView` · `ClipCardView` · `MenuBarView` · `SettingsView` · `OnboardingView` |

## 2. 组合根与启动流程

`App/EasyPasteApp.swift` 是入口，包含三个角色：

- **`EasyPasteApp`**（`@main`）：只声明一个 `MenuBarExtra` 场景，把 `services` 注入 `MenuBarView`。
- **`AppServices`**（`@Observable @MainActor`，**组合根**）：集中持有并接线所有单例——
  `settings`、`store`、`clipboard`、`shortcut`、`panelState`、懒加载的 `panel` 与 `settingsWC`。
  其 `boot()` 完成所有运行时装配：启动剪贴板监听、设置回调、创建面板控制器、注册快捷键、首次启动展示引导。
- **`AppDelegate`**：接收 AppKit 生命周期事件——`applicationDidFinishLaunching` 初始化 Sparkle 并调 `boot()`；
  `applicationWillResignActive` 触发一次 iCloud 备份；`applicationShouldHandleReopen` 重新唤起面板。
  静态属性 `invokingApplication` 记录"唤起面板时的前台 App"，作为粘贴目标回退来源。

**启动时序**：`init` 创建 `AppServices` → AppKit 启动 → `boot()` → 打开本地库（`DatabaseManager.open`）→ 全量载入内存 → 启动 `ClipboardService` 轮询 → 注册 `⌘⇧V` →（首启）展示 `OnboardingView`。

## 3. 核心模块

### 3.1 捕获层 — `ClipboardService`
`@MainActor`。负责把系统粘贴板的变化变成 `Clip` 并交给 store。

- **轮询捕获**：`Timer` 每 `0.45s` 检查 `NSPasteboard.changeCount`；变化时 `readIfChanged()`。
- **`makeItem()` 保真建模**：收集粘贴板上**所有 UTI 及其二进制数据**（`allPasteboardData: [UTIEntry]`），
  按 `RTF > HTML > 纯文本 > 图片 > 文件 > URL` 的 UTI 一致性优先级选首选类型；文本色值自动重分类为 `.color`。
- **隐私安全**：过滤 `org.nspasteboard.ConcealedType / TransientType / AutoGeneratedType` 标记（密码、临时、自动生成内容不落入历史）；`AppSettings.ignoredApps` 内的来源 App 整体跳过。
- **来源归因**：记录 `sourceApplication` / `bundleID`，并在创建时计算并持久化来源 App icon 的**主色调**（`CodableColor`），避免渲染时重复解码。
- **`copy(_:)` / `paste(_:)`**：`copy` 优先把 `allPasteboardData` 全部写回粘贴板（保真还原富文本/图片原始格式），回退到 `uti`/`utiData`，再回退到按 kind 的基础写入。`paste` = `copy` + 确保辅助功能授权 + 隐藏面板 + 通过 **HID 事件（⨉V，`CGEventTap`）** 注入目标 App（前台 App 优先，否则 `AppDelegate.invokingApplication`）——用 HID 而非 `postToPid` 是因为后者常被 App 忽略。

### 3.2 状态层 — `ClipboardStore`
`@Observable @MainActor`。内存单一事实源 + 写穿持久化。

- **状态**：`items: [Clip]`、`boards: [Pasteboard]`、`rules: [AutomationRule]`，以及过滤条件（`selectedBoardID / selectedKind / query / isFavoritesOnly`）。
- **`filteredItems`**：**每次访问都直接基于 `items` 过滤**，不缓存——这是关键正确性约束：缓存会让 SwiftUI 的 Observation 丢失对 `items` 的依赖，导致增删后列表不刷新。
- **写入路径**：`add(_:)` → 去重（`allPasteboardData` 哈希）→ 规则匹配分类（`rules.matches` 决定看板）→ 插入内存 → `writeClip`（同一事务 upsert `clips` + `clip_blobs`）→ 调度空闲备份。
- **保留策略 `pruneExpired`**：三维淘汰——按天（默认，0=无限）、按条数上限（`maxItems`）、按磁盘压力（库文件 >200MB 或卷可用空间 <500MB）。
- **看板与规则**：看板支持拖拽实时重排（带动画）→ 写穿 `sortIndex`；自动化规则按关键字 + 来源 App 匹配。

### 3.3 持久层 — `Database` + `DatabaseModels`
纯 Swift 的 **GRDB**（`Package.swift` 锁定 `7.11.1`）。

- **`DatabaseManager`**：建库路径 `Application Support/EasyPaste/db.sqlite`；迁移 `v1.0.0` 建 4 张表，`v1.0.1` 为看板加 `sortIndex`。所有访问在 `@MainActor`。
- **表设计**（**无外键**）：
  - `clips`：小字段（id/kind/createdAt/text/url/fileURLs/boardID/isFavorite/来源App/主色调/title）。
  - `clip_blobs`：`clipID` 1:1，存 `imageData / utiData / allPasteboardData`（二进制分离，列表查询不碰）。
  - `pasteboards`：看板（`sortIndex` 支持排序）。
  - `automation_rules`：自动化规则。
- **`DatabaseModels`**：GRDB 行适配器（`ClipRow / ClipBlobRow / PasteboardRow / AutomationRuleRow`），负责与内存 `Codable` 模型的双向映射，**不污染 `Models/Clip.swift`**。

### 3.4 面板控制 — `PanelController`
`@MainActor`。管理挂载在**非激活 NSPanel**（`.nonactivatingPanel`）上的屏幕边缘面板——关键在于唤起时不抢占前台 App 的焦点。

- 滑入/滑出动画、四向定位（底/顶/左/右）、点击外部或 `Esc` 自动隐藏。
- **键盘监控**：输入即搜索（`store.query`）、回车粘贴、`⇧↩` 纯文本、`空格` 预览、方向键选择、`⌘C` 拷贝、`⌘]` 切换看板。
- **粘贴前同步 `orderOut`**：必须先移除浮动面板，让目标 App 窗口重新成为 key window，否则 ⌘V 会被面板吞掉。
- **设置窗口**：`openSettingsFromPanel()` 先 `forceHidePanel()`（避免 `.floating` 遮挡），再调 `AppServices.openSettingsWindow()`。

### 3.5 快捷键 — `GlobalShortcutService`
Carbon `RegisterEventHotKey` 桥接，注册可配置全局热键（`⌘⇧V` 唤起、`⌘]` 切换看板），触发时回调解绑 app。

### 3.6 缓存 — `AppIconCache` / `ImageSizeCache`
- **`AppIconCache`**：缓存来源 App 的 icon 与主色调（中心区域平均色），用 `NSLock` 保证线程安全、不依赖 MainActor；`warm` 后台预热。
- **`ImageSizeCache`**：图片尺寸描述（只读 `CGImageSource` 元数据，不解码像素）；卡片缩略图未命中时在后台按 340px 降采样，完成后经 `@Observable` 触发卡片刷新，避免滚动时主线程解码大图。

### 3.7 备份 — `BackupService`
iCloud ubiquity 文件级备份。**单写者假设**：绝不在 ubiquity 内高频开库。策略：本地库高频读写；后台定时（5min）/ 空闲 debounce 对本地库做 **GRDB 一致性快照**（`sourceDb.backup(to:)`），再用 `FileManager.replaceItemAt` **原子替换** ubiquity 内 `db.sqlite` 触发上传。无 iCloud 账号时静默跳过。

### 3.8 设置 — `AppSettings`
`@Observable`，持久化到 `UserDefaults`（JSON `Snapshot`，`decodeIfPresent` 兼容旧存档）。涵盖：面板位置、登录启动、iCloud 同步、菜单栏显示、音效、纯文本粘贴、历史保留时长、最大条数、忽略 App、两个快捷键、引导完成标记。通过 `onHistoryLimitChanged / onMaxItemsChanged / onStorageLocationChanged` 回调回写 `ClipboardStore` 与 `BackupService`。

> **设置窗口实现要点**：macOS 14+ 已移除 `showSettingsWindow:` 选择器，且 SwiftUI `openSettings` 环境动作对"只用快捷键唤起面板"的用户恒为 `nil`。因此设置窗口由 `AppServices` 用 **AppKit `NSWindow` + `NSHostingController`** 自行托管（`openSettingsWindow()`），从面板与菜单栏都能稳定打开。

## 4. 端到端数据流

### 4.1 捕获 → 存储 → 持久化
```
NSPasteboard 变化
  → ClipboardService.readIfChanged() [0.45s 轮询]
  → makeItem(): 收集 allPasteboardData + 来源 App + 主色调 + 安全标记过滤
  → onItem 回调 → ClipboardStore.add(item)
      ├─ 去重(hash) → 规则分类(boardID)
      ├─ items.insert(0)            [内存]
      ├─ writeClip(): clips + clip_blobs upsert [GRDB 同一事务]
      └─ scheduleBackupOnIdle()    [BackupService]
```

### 4.2 持久化 → 内存重建（冷启动）
```
DatabaseManager.open(url) → migrator
  → ClipboardStore.load()
      ├─ reloadItems(): clips + clip_blobs → items
      ├─ pasteboards → boards (空库播种默认看板)
      └─ automation_rules → rules
```

### 4.3 展示 → 交互
```
PanelController (非激活 NSPanel)
  → hosts PanelView (SwiftUI)
      ├─ store.filteredItems → ForEach ClipCardView
      ├─ 键盘/搜索/看板筛选 → 仅改 store 查询条件 (纯内存)
      └─ 选中/粘贴/拷贝/固定/重命名/删除 → 调 store/clipboard 方法
            └─ 内存变更 + 写穿 GRDB (+ 调度备份)
```

### 4.4 粘贴 → 目标 App
```
用户回车 / 双击卡片
  → ClipboardService.paste(item)
      ├─ copy(item): 全部 allPasteboardData 写回 NSPasteboard (保真)
      ├─ ensureAccessibilityPermission() (必要时弹系统授权)
      ├─ PanelController.forceHidePanel() 让出 key window
      └─ HID ⌘V → 目标 App (前台 App 或 invokingApplication)
```

### 4.5 配置回写
```
SettingsView 改 AppSettings
  → didSet { save() } + onXxxChanged?()
  → AppServices 回调 → store.historyLimitDays / maxItems / pruneExpired
                     → backup.setEnabled() / backupNow()
```

### 4.6 备份上传
```
每次写入 → scheduleBackupOnIdle() (1s debounce)
iCloudSync 开启时:
  BackupService.backupNow()
    → GRDB 一致快照 → 临时副本
    → FileManager.replaceItemAt 原子替换 ubiquity/db.sqlite → 触发 iCloud 上传
```

## 5. 关键设计决策与约束

| 决策 | 理由 |
|------|------|
| 内存单一事实源 + 写穿 SQLite | UI 零延迟读内存；SQLite 仅做耐久性；避免旧 `history.json` 全量重写与二进制内联 |
| 二进制分离到 `clip_blobs` | 列表查询只 SELECT `clips` 小字段，不解码图片/RTF |
| 无外键 | 为阶段二 Harmony / CloudKit 多设备同步铺路，避免返工 |
| 非激活 NSPanel | 唤起面板时不抢前台 App 焦点（剪贴板管理器核心体验） |
| 存储 `allPasteboardData` 全格式 | 粘贴时**保真还原**来源格式（富文本/图片原始 UTI），而非降级为纯文本 |
| HID 注入 ⌘V | `postToPid` 不被多数 App 接受；HID 事件与真实按键无异 |
| AppKit 托管设置窗口 | 绕过 macOS 14+ 移除的 `showSettingsWindow:` 与不可靠的 `openSettings` 环境动作 |
| `@MainActor` 统一 GRDB 访问 | 单写者，避免并发；`DatabaseQueue` 为 Sendable |
| 缓存线程安全 + 后台预热 | `AppIconCache`/`ImageSizeCache` 用 `NSLock`，避免主线程解码大图与 icon |

## 6. 模块依赖关系（编译期）

- `App` → `Stores` / `Services` / `Views` / `Models`
- `Services.ClipboardService` → `Models` / `Stores` / `AppIconCache`
- `Stores.ClipboardStore` → `Database` / `DatabaseModels` / `BackupService` / `Models`
- `Views.*` → `Stores` / `Services` / `Models`
- `Models` 除 `AppSettings`（依赖 `Shortcut`）外基本自洽
- 外部依赖仅 **GRDB**（持久化）与 **Sparkle**（自动更新，`#if canImport` 条件编译，SPM 命令行构建跳过）

> 构建体系：仓库同时含 `Package.swift`（SwiftPM，真实构建路径，`script/build_and_run.sh` 用 `swift build`）与 `EasyPaste.xcodeproj`（Xcode 分发/签名与可视化编辑）。两者锁定同一 GRDB 版本（7.11.1），无漂移。

## 7. 后续演进方向（已知）

- **阶段二 Harmony / CloudKit**：在"无外键 + UUID 关联 + 单写者本地库"基础上接入多设备增量同步；`BackupService` 的 ubiquity 逻辑已按此预留。
- **并发**：目前 GRDB 访问全在 MainActor；未来若需后台导入，可迁移到 GRDB 的并发 `DatabaseReader` 配合 actor 隔离。
- **检索/分页**：当前 `filteredItems` 为内存全量过滤（配合 2000 条默认上限）；超大数据集时应在 `clips` 表上加索引分页（索引已建 `createdAt`）。
