# 2026-07-23

## 修复"唤起后无法粘贴进目标 app"

根因（多处叠加）：
1. `requestAccessibilityIfNeeded` 用 UserDefaults 一次性门控，辅助功能未授权时静默失败（ad-hoc 签名重打包后 TCC 身份失效，不再提示）。
2. 粘贴按键用 `CGEvent.postToPid`，绕过 HID 层，很多 app 会忽略。
3. 固定 0.35s 延迟，激活是异步的，时序不稳。
4. `invokingApplication` 只在快捷键路径记录，且本 app 前台时会被清空；菜单栏粘贴时目标不可靠。
5. 卡片外层单击手势与卡片双击手势竞争，双击可能不触发。

修改：
- `Services/ClipboardService.swift`：paste 流程重写 — copy → `ensureAccessibilityPermission()`（未授权每次都弹系统提示 + 应用内 NSAlert 可跳设置）→ 目标解析（当前前台非本 app 则用前台，否则用 `AppDelegate.invokingApplication`）→ `NSApp.hide` + `activate([.activateAllWindows])` → 轮询等目标真正前台（~1s 上限）→ 用 `CGEventSource(.hidSystemState)` 向 `.cghidEventTap` 发 ⌘V。
- `App/EasyPasteApp.swift`：`invokingApplication` 改 `private(set) static` 暴露读取；快捷键在本 app 前台按下时保留原目标；删除 `returnToInvokingApplication`；MenuBarExtra 加 `.menuBarExtraStyle(.menu)`。
- `Views/ContentView.swift`：单击/双击手势都放到 ClipCard 上（双击声明在前），通过 `onSelect` 回调选中，移除外层手势。

环境备忘：WorkBuddy 沙箱里 SwiftPM 的 sandbox-exec 会 posix_spawn 失败，需 `swift build/test --disable-sandbox`；`script/build_and_run.sh` 未加该参数，本次手动执行了 build+bundle+codesign+open。

注意：重打包后 ad-hoc 签名身份变化，用户可能需在 系统设置→隐私与安全性→辅助功能 中重新启用 EasyPaste（可删掉旧条目）。

编译注意：
- Swift 并发：NSAnimationContext 的 completionHandler 是 @Sendable，访问 @MainActor 属性会有 warning（非 error），可忽略。
- `MainActor.assumeIsolated` 不能用（NSEvent 非 Sendable）；本地事件监控闭包直接调 MainActor 方法即可（当前为 Swift 5 语言模式）。
- `if let x { ...; x = nil }` 会因常量遮蔽报错，改 `if let m = x { ... }; x = nil`。
- 大型 ViewBuilder 表达式（ClipCardView 多闭包内联）会让类型检查超时，抽成独立 `clipCard(for:)` 方法解决。
- `override acceptsFirstMouse` 在该 SDK 签名不匹配→删掉（非激活面板 makeKey 后点击仍可用）。

dist 已重打包签名启动（PID 稳定无崩溃）。终端无辅助功能权限，无法自动模拟 ⌘⇧V 验证面板，需用户手动测试。粘贴仍可能需重新授予辅助功能权限。

## 修复面板版两个 bug

### Bug: 粘贴失效（音效播放但不粘贴）
根因：非激活 NSPanel 是 key window。粘贴时 `waitForTargetFocus` 发现目标 app 本就是 frontmost（非激活面板不抢前台），settled=true 立即发 ⌘V——但面板仍是 key window，按键被面板吞掉。
修复：
- `PanelController.paste`：先 `panel?.orderOut(nil)` 同步移除面板（resign key），再调 `clipboard.paste`。
- `ClipboardService.waitForTargetFocus`：settled 条件加 `NSApp.keyWindow == nil`——等面板真正 resign key 后再发按键。
- `ClipboardService.performPaste`：移除 `NSApp.hide(nil)`（非激活 app 不需要，且可能干扰前台状态）。

### Bug: 设置窗口打不开
根因：`.menu` 样式 MenuBarExtra 里 `@Environment(\.openSettings)` 不生效；面板里 `sendAction` 没等激活完成就发了。
修复：MenuBarView 和 PanelView 的 openSettingsWindow 统一改为：`NSApp.activate` → `DispatchQueue.main.async { sendAction(showSettingsWindow:) }`，并 fallback `showPreferencesWindow:`。

### Bug: 设置窗口仍打不开（sendAction 在 macOS 14+ 已被移除）
根因：macOS 14 (Sonoma) 起，Apple **完全移除**了 `NSApp.sendAction(Selector(("showSettingsWindow:")))` 的能力。无论怎么延迟/激活都没用。
正确做法（三处入口）：
- **MenuBarExtra（.menu 样式）**：用 `SettingsLink { Text("设置…") }`——Apple 官方组件，自动打开 Settings 场景。
- **面板 NSPanel（不在 SwiftUI Scene 树内）**：`EnvironmentValues().openSettings()` + `NSApp.activate(ignoringOtherApps: true)`——通过 EnvironmentValues 直接调用 openSettings 动作，无需 View 上下文。
- **Settings 场景**：SettingsView 加 `.onAppear { NSApp.setActivationPolicy(.regular); NSApp.activate(ignoringOtherApps: true) }`——确保窗口出现时 app 激活、窗口置前（SettingsLink/openSettings 不一定自动激活 app）。
